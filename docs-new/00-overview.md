## Введение

Casino Backend — это высоконагруженная микросервисная платформа для онлайн-казино, построенная на современных принципах архитектуры и разработки. Проект следует единой архитектурной парадигме для всех сервисов, обеспечивая консистентность, масштабируемость и поддерживаемость системы.

---

## Технологический стек

### Основные технологии

- **NestJS** — фреймворк для построения серверных приложений на Node.js
- **CQRS (Command Query Responsibility Segregation)** — разделение команд и запросов для оптимизации производительности и масштабируемости
- **Clean Architecture** — архитектурный подход с разделением на слои (Domain, Application, Infrastructure)
- **Monorepo** — единое репозиторий для всех сервисов и библиотек
- **NATS** — высокопроизводительная система обмена сообщениями для межсервисной коммуникации

### Дополнительные технологии

- **TypeScript** — типизированный JavaScript для повышения надежности кода
- **PostgreSQL** — реляционная база данных для хранения данных
- **Docker** — контейнеризация приложений
- **Kubernetes** — оркестрация контейнеров (предположительно)

## Архитектурные принципы

### 1. Единая архитектура для всех сервисов

Все сервисы в проекте следуют единой архитектурной модели:

```
┌─────────────────────────────────────────┐
│         Presentation Layer              │
│    (HTTP Controllers, GraphQL)          │
└─────────────────────────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│      Application Layer (CQRS)           │
│  ┌─────────────┐    ┌─────────────┐   │
│  │  Commands   │    │   Queries   │   │
│  └─────────────┘    └─────────────┘   │
│  ┌─────────────┐    ┌─────────────┐   │
│  │  Handlers   │    │   Handlers  │   │
│  └─────────────┘    └─────────────┘   │
└─────────────────────────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│         Domain Layer                     │
│  (Entities, Value Objects, Domain Logic) │
└─────────────────────────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│      Infrastructure Layer                │
│  (Repositories, External Services, NATS)│
└─────────────────────────────────────────┘
```

### 2. CQRS (Command Query Responsibility Segregation)

- **Commands** — операции изменения состояния (создание, обновление, удаление)
- **Queries** — операции чтения данных (без изменения состояния)
- Разделение позволяет независимо масштабировать чтение и запись
- Оптимизация производительности через специализированные модели данных

### 3. Clean Architecture

Слои архитектуры:

1. **Domain Layer** — бизнес-логика, не зависящая от фреймворков и инфраструктуры
2. **Application Layer** — use cases, обработчики команд и запросов
3. **Infrastructure Layer** — реализация репозиториев, внешние интеграции, базы данных
4. **Presentation Layer** — HTTP контроллеры, GraphQL resolvers, валидация входных данных

### 4. Monorepo структура

Преимущества:
- Единая версионность зависимостей
- Переиспользование кода между сервисами
- Атомарные изменения across сервисов
- Упрощенное тестирование интеграций

### 5. NATS для межсервисной коммуникации

- **Request-Reply** — синхронная коммуникация для запросов с ответом
- **Publish-Subscribe** — асинхронная коммуникация для событий
- **Queue Groups** — распределение нагрузки между инстансами сервисов
- Высокая производительность и низкая латентность

## Ключевые особенности

### Масштабируемость

- Горизонтальное масштабирование через Kubernetes
- Независимое масштабирование чтения и записи благодаря CQRS
- Распределение нагрузки через NATS Queue Groups

### Надежность

- Изоляция сервисов предотвращает каскадные сбои
- Event-driven архитектура обеспечивает отказоустойчивость
- Транзакции и саги для распределенных операций

### Производительность

- Оптимизированные запросы через специализированные Query модели
- Асинхронная обработка через NATS
- Кэширование на уровне приложения и базы данных

### Поддерживаемость

- Единая архитектура упрощает onboarding новых разработчиков
- Clean Architecture обеспечивает тестируемость
- Monorepo упрощает рефакторинг и переиспользование кода
